【Canvas 嵌入交互（硬门槛相关）】
- 文件卡片内容默认被 .canvas-node-content-blocker 遮罩拦截鼠标；须先点击节点聚焦（is-focused），blocker 才 display:none，代码块控件才可交互。
- 防误拖：交互容器上 pointerdown/mousedown/touchstart/dblclick 只 stopPropagation、不 preventDefault——保住输入默认行为，节点标题区拖动留给 Canvas 原生。实机断言节点 style.transform 全程不变。
- 缩放手柄是 Canvas 原生 chrome（仅 is-selected 态出现），位于代码块之外，插件无法影响；自动化点击只能到 is-focused、难触发 is-selected，故 resize 列为手动验收项（非插件缺陷）。

【实机验收（CDP）踩坑】
- 插件重载后，已渲染的 markdown 视图不会自动套用新处理器；须 leaf.rebuildView() 强制重建（或重开文件），否则看到的仍是旧 DOM。
- canvas-node-content 是 overflow:hidden：超出节点高度的子表内容被裁剪，深层按钮落在节点外，视口真实点击点不到。验收时放大节点容纳内容，或对深层按钮用合成 el.click() 驱动真实 AbortController 监听器（首格仍用真实 Input 点击证明可信输入）。
- canvas:zoom-to-fit 对超大节点不一定缩放进视口（节点仍按原像素渲染，工具栏按钮跑出屏幕）；真实点击前先确认目标坐标在视口内。
- canvas 文件保存有防抖：移动/缩放断言用 DOM node.style.transform 即时值，别读 .canvas 文件（会读到旧值）。
- Canvas 节点运行态对象 n.file 是 TFile 对象（含循环引用），CDP returnByValue 序列化报 "Object reference chain is too long"；取路径用 n.filePath（字符串）。节点类型读 .canvas 文件 JSON 的 nodes[].type，运行态对象不暴露 n.type。
- app.plugins.disablePlugin(id) 只卸载运行实例（app.plugins.plugins[id] 变 undefined），不改持久化 enabledPlugins 集合；判断「真禁用」看 plugins[id] 实例是否存在，不能只看 enabledPlugins.has()。「禁用后文件保留」验收以实例卸载 + 文件仍在为准。

【数据保护】
- 损坏 JSON / 不支持 formatVersion / 缺失文件 → 可读中文错误面板，init 阶段即 renderFatal，绝不触发保存、绝不覆写或新建文件（实机逐字节比对确认）。
- 外部修改：Vault.process 内比对磁盘内容与上次自写内容，不一致即停自动保存 + 横幅提示重新载入（确认后才丢弃本地改动重载）。

【UI 阅读优先（按钮墙修复）】
- 深层嵌套时所有操作按钮常驻会把内容糊成按钮墙。改为阅读优先：toolbar 动作按钮、列×、行×、单元格+子表、展开态折叠 toggle 默认 opacity:0 + pointer-events:none，悬停/键盘聚焦（:hover / :focus-within）到对应区域才浮现。
- 无子表的单元格用 .nct-empty-child 容器 max-height:0 + overflow:hidden 收起，不预留按钮空位；悬停才展开。有子表的容器 .nct-has-child 正常占位。
- 折叠态 toggle 加 .is-collapsed 常驻显示，便于发现被收起的子表。
- 验证「按钮是否隐藏」要测有效可见性（容器高度/opacity），别只测按钮自身 opacity——+子表自身 opacity 恒为 1，靠父容器收起隐藏。

【插件热重载缓存】
- 实测（2026-11-14）：location.reload() 并不刷新插件 main.js 的模块缓存——重载后命令/设置仍是旧代码，尽管磁盘 main.js 已是新构建。正确做法是 app.plugins.disablePlugin(id) → enablePlugin(id) 重新注入运行实例，再 leaf.rebuildView() 重建已渲染视图。改渲染逻辑后按此顺序验收，否则看到旧代码。
- disablePlugin → enablePlugin 会重新注入 styles.css；若只改 CSS 可不必整窗重载。

【OneNote 式文档表格（去按钮墙二期）】
- 用户参照 OneNote 医学表格：要有意义的可编辑列名（病史/症状/体征/检查）、嵌套子表是带自己表头的真实表格、阅读态无任何标题栏与按钮。据此把 columns 从「col_id 唯一标识」改为「可编辑表头文字」（默认 列 N），删除按索引；旧 col_id 数据在 store.load 时经 normalizeColumnHeaders 递归迁移为 列 N，校验放宽为「至少一列、均为字符串」（允许空/重名表头）。
- 去掉 .nct-title 标题栏与常驻工具栏：工具栏改 position:absolute 浮于表格右上角，默认 opacity:0，仅 :hover/:focus-within 浮现；表头用主题变量 --background-secondary-alt 填充底色适配明暗主题，不硬编码颜色。
- 单元格富文本（高亮/彩色小节头）属更大特性，本轮不做，保持纯文本 contenteditable。

【CDP 验证：画布隐藏重复渲染】
- 一个 canvas 文件节点在 DOM 里可能对应多个 .nct-wrap（Obsidian 内部保留隐藏副本），querySelectorAll 会把隐藏副本与嵌套子表一起算进去，导致「列名数量/迁移」断言误报。验证时整窗重载后取首个 wrap，且根表头用 `> .nct-table-block > .nct-table > thead .nct-colhead` 限定（子表在根表单元格内，属后代，须用 >thead 排除）；可见性以截图为准（用户只见单表）。
- 自动保存防抖 600ms：创建/编辑后读盘断言须等 ≥900ms，否则读到旧值误判「未持久化」。

【格式右键菜单（#8）】
- Obsidian 桌面端 Menu 默认走原生菜单（无 DOM），CDP 查 .menu-item 为空、也无法主题化。须 menu.setUseNativeMenu(false) 强制 DOM 菜单，才能验收与套主题。
- MenuItem 有 setChecked 但无 setSubmenu；颜色/底纹用「文字颜色：红」「底纹：红晕」等分组扁平项 + setChecked 标示当前值，不做二级子菜单。
- 单元格模型改为「markdown 源码」：cell.text 存源码，聚焦态 contenteditable 显示源码、失焦态用自研 renderInlineMarkdown 渲染（仅 ** * == ~~ ` 五种、不嵌套、createElement/textContent 安全渲染）。formatVersion 仍为 1，无需迁移；style 仅 {bg?,color?} 白名单 token，validate 递归校验。
- 包裹语义：有选区则包裹选区，无选区在光标处插入成对标记；applyWrap 读 selection 偏移时注意 anchorNode 可能是编辑器 div 本身（此时 startOffset 是子节点索引而非字符偏移），无选区统一回退到 cell.text.length。

【新手引导（#9）】
- openDemo 曾把 columns 设成 4 列却沿用 createDocument 默认 3 列的行单元格，doc.rows[0].cells[3] 为 undefined 直接崩溃、引导永不弹出。改列数时必须同步重建行单元格（createRow(4)）。
- 引导覆盖层 .nct-tour 挂 document.body，高亮环 .nct-tour-ring 按目标 getBoundingClientRect 定位；Enter 下一步、Esc 跳过；「不再显示」双置 onboarded=true 且 showHints=false；首次运行 startTour(true) 即使跳过也置 onboarded=true。重开示例（openDemo）不碰这两个标志。

【CDP 验收夹具污染与聚焦】
- 复用旧卡片/画布做验收会被早期失败运行污染：卡片可能被塞入垃圾前缀与多个 nctable 块，指向不同 data 文件，导致两个 .nct-wrap 写到不同文件、断言读错文件恒为空。验收应建专用干净夹具（单 nctable 块 + 独立 data/card/canvas），别复用业务夹具。
- 重置 data 文件须先卸载持有它的视图（detach leaf）再 modify 再重开；视图开着时外部 modify 会触发 store 冲突保护停写，且 modify 事件会 race 到新 store。
- canvas-node-content-blocker 只拦截指针事件，不挡程序化 focus：验收聚焦单元格直接 el.focus() 即可，无需真实点击/双击进入节点编辑态（双击反而可能触发画布缩放/重渲染干扰）。

【右键落点穿透（子表表头误染父格，2026-11-15 用户报障修复）】
- 症状：选中子表列头文字右键改颜色，颜色却落到包裹子表的父单元格。根因：子表整体 DOM 在父 td 内，contextmenu 用 e.target.closest(".nct-cell-td") 会从子表表头/工具栏一路向上命中父 td。
- 修复：① 落点限定——target.closest(".nct-table-block") 必须等于 td.closest(".nct-table-block")，否则不弹格式菜单（嵌套 chrome 不穿透）；按钮右键一律留给原生菜单。② 列头独立菜单——.nct-colhead 带 data-col、表块带 data-path（JSON 路径），经 tableAtPath 定位所属表；表头样式存 Table.columnStyles（与 columns 等长、null 占位、全 null 时整体删除），addColumn/removeColumn 同步 push/splice，validate 校验长度与 token。表头不渲染 markdown，菜单只含颜色/底纹/清除/复制/粘贴。
- 验收：表头橙/底纹落 columnStyles 且 th 生效、父格 style 不变；清除回收；子表格/父格菜单回归；工具栏右键不弹格式菜单。9 项实机 PASS。

【选区变色/悬浮控件/行列拖拽/图片/一键新建（#10–#14，2026-11-15）】
- 变色只染选区：wrapSelectionColor 把选区包成 <span style="color:#RRGGBB"> 存源码；解析器升级为递归嵌套（深度封顶 12、span 颜色白名单、代码/图片作叶子），覆盖旧「不嵌套」说法。渲染态拖选会触发 focus→源码换态摧毁选区：focus 监听先记住选中可见文字，换态后按 indexOf 恢复选区，保证「选哪染哪」。
- Canvas 靠**冒泡期 click** 进入节点编辑态；编辑态下真实 pointerdown 落在非聚焦区域（拖拽手柄）会被焦点代理显式夺焦（activeElement 变 embed-iframe is-controlled），预览整体折叠成 0×0。对策：容器冒泡阻断清单加入 click/keydown——表格自身即编辑面，表内点击不进入节点编辑态，CodeMirror 也拿不到 keydown 改源码。节点拖动仍留给标题区。
- Canvas **双击文件节点会在新标签打开文件**（画布隐藏、几何全 0）。验收解除 blocker 用两次单击（首击选中节点、次击进入内容聚焦），别用双击。合成 dblclick 同样不能冒泡到节点（手柄自身 handler 已 stopPropagation）。
- rebuildView 会在 DOM 留下隐藏旧视图实例，节点含相同文本：querySelector 首匹配命中隐藏实例（rect 全 0、选区 toString 空）。验收查询一律先按 getBoundingClientRect().width>0 选可见节点；setup 打开文件后别多余 rebuildView。
- 列宽混合 null 语义：双击重置后该列 null。fixed 与 null 并存时用 auto 布局 + 仅非 null 列写 th width（重置列真自适应）；全非 null→fixed+总宽；全 null→回收数组。旧「null 回退 120px」会让重置看似无效。
- insertText 焦点兜底：插入后若 document.activeElement 不是编辑器（画布未编辑态焦点被夺），直接 paintCell 渲染，粘贴图片立即可见、不裸露源码。
- 验收脚本开头必须 disable/enable 插件加载最新构建，否则断言旧代码（提示条文案等）；提示条/几何断言限定可见节点，避开隐藏旧视图。
- 一键新建三分支：画布 active→vault.process 右侧追加节点（x=maxRight+60）；MarkdownView→editor.replaceSelection 插代码块；其余→新开卡片并打开。ribbon/命令/编辑器菜单共用 quickCreateTable/createTableData。

【按钮遮挡文字 → 悬停预留槽（2026-11-15 用户报障修复）】
- 症状：+子表/× 绝对定位悬浮直接压在单元格文字上，文字难点中。修复改「悬浮覆盖」为「预留槽」：.nct-cell-box 静止 padding-right:8px，td:hover/:focus-within 让槽到 --nct-gutter:44px，chip/× 绝对定位只落槽内；表头同法 26px；子表区 .nct-cell-child.nct-has-child:hover/:focus-within 顶部让槽 --nct-strip:28px 容纳 ▼折叠/子表工具栏。让槽条件==控件浮现条件（含祖先 hover 同时打开嵌套槽），结构上保证「可见即不压字」；折叠态 td.nct-collapsed 常驻右槽。
- 坑：▼折叠 浮现条件若用 td:hover 而让槽条件用 childArea:hover，悬停父格时按钮出现但槽不开→仍遮挡。两者统一为 .nct-cell-child.nct-has-child:hover/:focus-within。
- 验收：静止 pad 8px；悬停 pad≥40 且 chip.left≥editor.right-1、del.left≥editor.right-1；截图确认父格文字/子表头均不被工具栏压。

【CDP 验收：后台窗口不派发 focus/blur 事件（易误判产品回归）】
- Obsidian 窗口不在 OS 前景时 document.hasFocus()=false，element.focus()/blur() 只改 activeElement、不派发 focus/blur 事件→「失焦渲染」等断言全 FAIL，而落盘/菜单等不依赖事件的断言仍 PASS。Page.bringToFront 只激活标签页不拿 OS 焦点；osascript System Events 无辅助访问权限被拒。
- 正解：页内 require("electron").remote.BrowserWindow.getAllWindows().find(w=>w.getTitle().includes("nctable-test-vault")).focus()（Obsidian renderer 有 node integration、remote 可用），等 ~400ms 后 hasFocus=true，真实 blur 即派发。验收脚本开头统一做。
- 叠加坑：nct-89 旧版全局 querySelector(".canvas-node …") 命中其他套件遗留的隐藏旧视图（rect 0）：focus 静默失败、写入落在被冲突保护停写的旧 store。统一开头 disable/enable 加载新构建 + detach 全部 leaves + 按 rect.width>0 定位可见节点后 ALL_PASS。
