# 嵌套表格 Nested Canvas Tables

在 Obsidian 原生 `.canvas` 画布中摆放可编辑表格卡片，单元格内可递归创建子表格。

- 表格卡片是普通 Markdown 文件，内含 `nctable` 代码块；画布只用标准 `file` 节点，不碰 Canvas 内部接口。
- 表格数据存为 Vault 内独立 JSON 文件（默认根目录 `NestedTables/`，可在设置中修改），代码块以 Vault 绝对路径指向数据文件，移动画布不断链。
- 编辑自动保存（防抖 + `Vault.process`）；数据文件损坏、缺失或被外部修改时停止写入并给出可读提示，绝不静默覆盖。
- 阅读优先（OneNote 式文档表格）：列名是可编辑文字（默认「列 N」，可改成「病史/症状/…」），表头用主题底色填充；无标题栏、无常驻按钮——增删行列、子表等操作控件默认隐藏，悬停或键盘聚焦到对应表格/行/列/单元格时才浮现，深层嵌套也不会变成按钮墙；折叠的子表保留一个小标记便于发现。
- 嵌套子表是带自己表头的真实表格，可逐层递归；旧版 `col_id` 表头数据在加载时自动迁移为「列 N」。

## 命令

- **新建带表格的画布**：创建表格卡片 + JSON 数据 + 合法 `.canvas` 并打开。
- **新建表格卡片**：只创建卡片与数据文件，用 Canvas 自带的「添加文件」或拖放放入现有画布。

## 开发

```bash
npm install
npm run build      # 产物目录：NCT_OUT > dev.config.json > ./dist
npm run dev        # watch
npm test           # node --test（纯逻辑单测）
npm run typecheck  # tsc --noEmit
```

本机开发约定：`dev.config.json`（gitignored）的 `out` 指向独立测试库 `nctable-test-vault` 的插件目录；踩坑记录见 `踩坑.txt`。

## 限制（MVP）

- 单元格仅纯文本 + 可选子表格；无公式、合并单元格、排序、富文本。
- 移动端未实机验证。
- 数据文件被手动改名后路径失效，显示可读错误（不自动跟踪）。

## 验收（独立测试库实机，CDP 驱动）

七条验收标准均已实机通过：

1. 构建加载、两条命令正常（「新建带表格的画布」生成标准 `file` 节点 `.canvas` 并打开；「新建表格卡片」生成 md+json）；设置页「数据根目录」可改、持久化生效并影响命令输出。
2. 原生 Canvas 打开文件卡片即可编辑表格。
3. 三层嵌套（单元格→子表→孙表）创建、折叠/展开正常。
4. 关闭重开后数据完整（嵌套层级、文本、行列数均持久化）。
5. 画布平移/缩放/节点移动正常；在表格内输入、点击控件不会误拖节点（全程断言节点位移不变）。
6. 数据文件损坏 / 缺失 / 版本不支持时显示可读中文错误，绝不覆写或新建文件（逐字节比对确认）。
7. 禁用插件后数据与画布文件保留，重新启用正常。

已知限制：节点缩放手柄属 Canvas 原生 chrome（仅选中态出现，位于代码块外），自动化难以触发选中态，resize 列为手动验收项；插件本身不影响该原生行为。详见 `踩坑.txt`。
